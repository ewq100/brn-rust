# BRN Threads invariant summary

These summarize the [canonical Threads target](threads-target.md). They are obligations of the implemented core; [status](../status.md) distinguishes demonstrated checks from remaining gaps.

1. **One authority.** SQLite owns live BRN work. A Markdown export or derived index cannot independently become current state.
2. **One write boundary.** UI, built-in agent, CLI, and eventual external agents use the same checked service. Generated scripts and tools cannot bypass it with raw canonical SQL.
3. **Coherent changes.** Related records, revisions, source observations, selected assets, and the operation receipt commit together. Long model calls and source fetches remain outside the transaction. The SQLite writer boundary serializes processes, not merely callbacks in desktop memory.
4. **Versioned preconditions.** Check the expected current record version at commit time, including relevant protection, metadata, lifecycle, and content pointers. Declared current-read inputs also require their exact active version at commit; explicitly historical citations retain provenance without that current-state claim. Reject stale work; refresh it under applicable authority.
5. **Durable operation identity.** Repeating an operation with the same identity and contents returns its recorded outcome. Reusing an identity for different content is an error. The trusted host records the identity before preparation; both immutable prepare and apply replay it. A lost response at either boundary cannot cause a duplicate mutation.
6. **Host-owned authority.** Explicitly chosen standing delegation, an applicable direct owner instruction, or exact-candidate review supplies authority. Missing, archived or unchosen workspace Settings cannot grant standing maintenance; fresh workspaces start pending. Policy choices preserve unrelated configuration and fence current runs inside the checked writer. The model cannot manufacture confirmation receipts or expand a grant by citing arbitrary message IDs. Grants bind targets and operations; context membership or thread links never confer protected-write authority.
7. **Protection is not truth.** Ordinary maintenance excludes protected notes and structural ways to hide, unprotect, archive, or supersede them. Explicit confirmation belongs to a revision and is distinct from protection or source authorship.
8. **Human writing is coordinated.** Save carries a base version and edit-session/generation; stale typed work is preserved as a conflict. Persisted dirty guards coordinate all committers and survive recovery. A guarded member defers the whole group. Delayed autosave cannot recreate a closed guard or erase newer typing.
9. **Review fixes the result.** Acceptance binds the exact displayed candidate. Regeneration or an interdependent subset requires the refreshed result; approval cannot be reused for a later model rewrite.
10. **Undo preserves subsequent work.** A recorded compensation restores eligible prior state as new revisions/versions. Later conflicts remain visible and can require reviewed compensation. Local Undo does not reverse external delivery or provider usage.
11. **Current retrieval is explicit.** Default search includes current ordinary and protected notes, not pending candidates, older revisions, archived notes, or scratch. Do not mistake an imported source's claim for an adopted owner decision.
12. **Import intent determines coverage.** Useful-information intake may extract only relevant knowledge. Full-note import preserves complete substantive supplied content and required assets as a protected note. Partial coverage is visible; a summary cannot satisfy full import. Mathematical equation conversion/typesetting is outside the initial scope; unsupported substantive gaps remain visible.
13. **Original files stay external.** Temporary raw fetch/decoder payloads expire, including hidden copies in checkpoints/logs. Intentionally committed full notes and their assets are retained BRN knowledge. Keep small BRN-owned continuation records and receipts, not opaque serialized runtime/provider transcripts.
14. **Comments retain context.** Persist note/revision/range/quote and reliable supported mappings. An edited-away or unresolved target is not silently attached by guessing.
15. **Exports and backups are distinct.** On-demand Markdown/assets form a new snapshot destination. Full backup restores BRN state and retained assets, not external originals. Incomplete exports or interrupted work are not reported successful.
16. **Scope and outcomes stay honest.** Source instructions cannot grant tools or change provider/access. Runs respect the selected provider/account/model and supported reasoning effort, budget, interruption, and cancellation without silent fallback. The same holds for an owner-chosen helper model: an unavailable helper ends with a visible notice and no other model or account is substituted. Stop does not prove that upstream processing was cancelled. Actions need appropriate evidence for completion; preparing a reply is not sending it.
17. **Fresh schema preserves owner data.** Rebuild trials use explicit new directories. The new core checks distinct application/schema identity and rejects incompatible directory markers; a different filename alone is insufficient. Old data is left untouched; no migration, dual-writing layer, or compatibility runtime is required.
18. **Evidence names what was tested.** Code, successful checks, native usability, owner acceptance, and merge status are separate. Preserve repository protection and truthful failed/blocked results.

The [acceptance journeys](threads-target.md#acceptance-journeys) and [verification guide](../development/verification.md) turn these into concrete checks.

## Chat context and saved queue

Chat-only Note/Source scope is host-controlled configuration. Exact IDs, ranges, historical evidence, assets, comments, source observations and relationship endpoints obey the same chat visibility boundary. Autonomous maintenance exposed to unpromoted private documents cannot write general BRN context. Keep in BRN is a version-bound owner operation; it preserves the same note, protection, converted content, assets and Undo. Original binaries stay external.

Queue dispatch claims, posted owner Message identity and Run instruction association are durable checked state. Competing dispatchers cannot start the same claim twice. Run start binds the current claim atomically. Queue completion checks exact pending item/Message/Run and its checked persisted terminal fence/outcome; caller success alone cannot acknowledge it. Stop, Archive, failure and recovery pause without losing waiting messages. Resume invalidates old completion associations. Successful completion does not override pause. Composer recovery rejects stale generations and does not retain keystroke history.

Schema 3/4 adoption requires an external, verified pre-upgrade snapshot before schema 5 mutation, with competing writes excluded across snapshot and upgrade. Missing backup authority/path, active runs or dirty edit sessions leave the old format unchanged. Known older backups upgrade only their unpublished restore copy; the source snapshot remains unchanged.

## Projects

Project membership/settings/instructions are owner-only checked configuration. One chat has at most one project. Document sharing retains one Note; linked access includes its own retained sources/assets while other conversations and instructions remain separate. General search/export excludes private content. Knowledge-off blocks new general lookups but preserves explicit document links and existing conversation. Private provenance survives chat movement and Undo; maintenance cannot publish saved private discussion into general knowledge.

Project context changes fence affected live runs inside the writer and pause pending/waiting work. Host-added ChatContext inputs compare a saved Thread context epoch, rather than its mutable attention version; project inputs bind current membership/settings. Review attention cannot itself invalidate the proposal it presents. Schema-5 partial indexes keep project metadata/reference reads bounded independently of ordinary note count.

Deletion previews bind the current removed/retained/unfinished-Action sets. Dirty or stale affected work fails atomically. Every unfinished Action requires Keep outside or Cancel. Exclusive cancellations remain archived and cancelled; restoring the project never restores those cancelled/outside links. Trash records bind exact deleted versions; conflicts preserve recoverable state. Retained shared-document edits do not block or get overwritten by restoration. Full backups include project settings, memberships, Trash, drafts and retained content.

New private-context Actions retain a host-owned conversation scope even when linked to a shared/general document. Project deletion requires an explicit Keep outside/Cancel choice for unfinished Actions associated with retained documents too. Keep records independent retention; Cancel cannot revive through Project Restore. Existing terminal private Actions and their relationships go to recoverable Trash. Model proposals cannot change private scope or mark an Action independently kept.
