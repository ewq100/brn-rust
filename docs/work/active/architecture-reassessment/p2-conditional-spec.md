## Outcome and boundary

Import an actual EML containing a DOCX with a meaningful PNG. Preserve the email, attachment and image bytes; expose decoded email and useful document content, the actual image, and specific extraction gaps. AI may investigate this private evidence and revise a knowledge proposal with a related Action before any Source approval. The owner reviews the originals, extraction, tentative interpretation, reasons and exact proposed changes together; approves the displayed versions; and can restart to inspect the same evidence, current knowledge, history and Action.

The required second case contains multiple attachments: a supported DOCX and an unsupported XLSX retained and visibly unprocessed, with the same PNG appearing twice in the DOCX. Collections and budgets govern cardinality; neither the first example nor asset deduplication collapses occurrences. A second visual-rich Office fixture checks omission disclosure and inspection. PPTX evidence informs the common envelope, but P2 production conversion is limited to EML and DOCX; production PPTX selection remains later. Full XLSX, standalone-image intake, PDF/layout selection, MSG, mail connectors, external URLs/network fetching, autonomous authoritative changes and a general DrawingML renderer are excluded.

## Reuse and technical approach

The clarified candidate uses published BetterOffice **structured/Markdown export and package APIs**, rather than adopting P1's manual mapping as the production design. Pin `betteroffice-docx-edit`, `betteroffice-docx-parse` and `betteroffice-opc` at **0.3.0**, plus the previously evaluated `mail-parser = 0.11.8` (`full_encoding`); this is still a proposed production dependency choice. The focused check below found no newer published facade release requiring a pin change. P1's successful constrained helper remains evidence, but the larger export graph must be requalified inside that helper before production adoption. It does not qualify a shipping bundle or a hard RSS ceiling. The [published MIME API](https://docs.rs/mail-parser/0.11.8/mail_parser/) distinguishes actual parts from generated body alternatives; the [publisher's Rust API guide](https://docs.betteroffice.dev/docs/rust) identifies the higher-level exports, whose fit is established below against pinned source/fixtures rather than documentation claims alone.

### Captured evidence, not a second document authority

Introduce a versioned immutable extraction snapshot in WorkStore with verified private blobs. It is operational evidence, never Current knowledge. Snapshot identity binds the intake capture/version, original byte hashes, parser/adapter version and configured budgets, ordered source nodes, extracted content, asset hashes, occurrence locators and explicit gaps. Parent IDs distinguish email → attachment → document content/visual; byte hash alone is not source identity.

- Source nodes retain original filename/media type, exact bytes/hash and parent MIME-part locator. Email retains raw headers plus decoded From/To/Cc, subject, original Date/timezone, actual text/HTML alternatives, Message-ID/In-Reply-To/References when present and encoding problems. Missing IDs/authentication stay unknown; subject similarity never creates a thread ID. HTML-derived text is labelled derived; untrusted HTML is sanitized/inert, with no remote resources or script execution.
- Assets represent validated exact image bytes independently of occurrences. Each occurrence has its own ID, owning source node, package part/MIME part, relationship/CID, document-order location and snapshot content-range binding. Retain qualified alt/caption metadata; a separate authored picture title may be explicitly unavailable when no qualified exact mapping exists. Never infer that title from a nearby shape or another occurrence. Two occurrences may reference one asset; they cannot share a locator merely because the bytes match. Scope CID resolution to the actual MIME related container; ambiguous/missing targets are explicit gaps.
- Unsupported attachments are retained byte-for-byte as children with `unprocessed/unsupported` and a visible reason. They are neither converted nor included as factual evidence. MIME nesting/decoding failures retain useful safe content and visible gaps within budgets. Never describe unsupported XLSX as partial import.
- Snapshot write is staged and verified under private intake ownership before the receipt is committed; interrupted captures are reconciled through the existing private original-effect family. Backups/recovery must include referenced blobs and manifests; an orphan receipt is never a valid snapshot. Do not add a generic transaction framework.
- Deterministic quote selection binds exact extracted UTF-8 text and occurrence, snapshot identity and original locator. Converter wording and original wording are distinguished; normalized or model-generated text cannot become an original quotation. Immutable evidence survives later source changes and session deletion for history; freshness is separately checked for new approval.

The selected snapshot is the analysis input. Drafts and interpretations may persist without approval. Budget state, progress, partial/complete/unsupported status and Cancel are visible. At least input bytes, expanded bytes, part count/depth, decoded attachment bytes, image pixels, output bytes, time and AI work are bounded and configurable. State the actual consumed scope; refuse/truncate only with an explicit visible reason, never silently drop a central fact.

### Owned conversion and freshness

AppWorker owns a constrained helper process and any renderer child. Input is a copied public/private-intake payload passed through a bounded protocol; helper gets no vault/credential paths or provider credentials, no inherited secret environment, no network and no authority to save user knowledge. P1's pre-main `sandbox-exec` launch failed; its working alternative activates the native deny-default policy inside trusted helper startup before reading input. Preserve that ordering and fail closed if activation fails. Before shipping, qualify the packaged helper on the supported macOS versions against the same synthetic forbidden-file/network and process-tree tests; native API/distribution fit remains unverified. An App Sandbox helper is a possible later packaging alternative, not a requirement to add another framework in P2. Never broaden private-file access merely to make startup pass. Helper output is validated as untrusted bytes. Stop, timeout, disconnect where relevant and application shutdown cancel/join the complete process tree before another job is admitted; interrupted snapshots cannot approve or resume parsing implicitly. No automatic alternate converter.

Fresh original capture identity and snapshot version are checked before reserving analysis, admitting a late result and approving new effects. A new extraction or owner revision invalidates older pending review stamps. Immutable old snapshots remain readable history; they never substitute for a changed current input. Approval verifies retained manifest and blobs plus trusted internal receipt identity, not self-consistent client-provided hashes. Converter version changes create new snapshots rather than mutate approved evidence.

### One proposal lifecycle and useful grouped review

Keep independent consequences as existing atomic proposals grouped by intake analysis. A source-preservation unit contains the related Source Markdown and all required exact assets; a knowledge unit contains the new knowledge and any necessary predecessor-to-History transition; an Action unit contains its full typed Action change. Each has the existing editable version/stamp, comments, Reject and Rewrite. Revision of candidate wording does not mutate immutable extraction or image payloads.

Group review exposes originals and safe rendered inspection, extracted email/document wording, each meaningful visual, separately labelled tentative interpretations, specific unsupported/missing content, proposed destination/diff/Action and reasons. The owner can inspect a selected evidence locator from a proposal. Show completeness honestly, including a prominent gap when a central diagram cannot be represented. Retaining an original alone does not satisfy reviewability.

P1's fixture-generation/inspection tooling is not a production dependency selection. Reuse a qualified macOS original-preview facility where suitable and expose exact original export/inspection through CLI; verify DOCX rendering on the target Mac rather than assume a preview exists. Keep reflowed extraction distinct from original layout. Do not silently bundle Python or LibreOffice to satisfy this spec. If native preview cannot expose the meaningful original/omitted visual, that reviewability gate stays pending and needs a bounded preview decision; it does not authorize building a renderer.

Source preservation is **not required before investigation**. Before authoritative application, references to a not-yet-saved Source bind typed snapshot citations and planned Source identity/text. Selecting a dependent knowledge/Action proposal requires selecting or already applying its Source-preservation prerequisite. Workflow revalidates that dependency; plain `SourceVersion` must never pretend an unsaved file exists. Once the Source unit applies, resolve those references to its exact durable evidence/identity and verify the bound extraction bytes. A source wrapper edit that invalidates citations requires renewed preparation/review.

An optional Approve selected/all adapts the existing `GroupApprovalRequest` / `approve_proposal_group` and its stopped-member/receipt result. It captures the exact vector of displayed stamps and dependencies, adds dependency-aware preflight, then uses existing atomic apply units in dependency order. It is not a cross-proposal all-or-nothing transaction: show applied, refused and remaining units precisely if a late conflict interrupts the sequence; never silently apply a revised unit or retry it. A changed/rejected unit needs renewed review. No approval of mechanical conversion is required and no new batch recovery authority is introduced.
