# MCP discovery follows the edited endpoint

## Outcome and authority

Editing the MCP endpoint after discovery previously left the old destination's
metadata and approval controls visible. Approving that metadata could replace an
active endpoint-B policy with endpoint A. The metadata already labelled A and the
checked service approved A exactly; this is a UI freshness defect, not a runtime
grant bypass. The campaign authorizes this bounded existing-journey improvement.

The desktop now compares the current canonical endpoint in completion, display
and approval, retaining the captured context stamp. Late success or failure for a
changed endpoint is not installed; completed metadata/errors are hidden after an
edit, and stale approval is refused. Existing configured policy and transient
runtime input grants remain independent of this editable discovery draft.

The existing shared endpoint parser supplies canonical identity, including IPv6
normalization. A private completion method is used by the actual callback and
controlled tests; one private error enum carries status/discovery provenance.
No general async framework, dependency, transport, policy or grant change is added.
