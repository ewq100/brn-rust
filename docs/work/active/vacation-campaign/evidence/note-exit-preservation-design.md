## Smallest coherent owner boundary

Use one fallible preservation/admission operation in the existing `WritingPanel`/Note owner and one small desktop wrapper shared by Close and Cmd-Q. Reuse `note_changed` and the PR209 **authoritative session recheck**, but do **not** equate Reload's replacement policy with exit's byte-preservation policy. A closed or different-generation session alone must not permanently prevent exit.

The decision is about the exact held Note ID and exact visible UTF-8 bytes:

- No Note, or an unchanged accepted Note with no local attempt, may exit normally. Do not turn every dirty/recoverable session into a mandatory Save dialog.
- An actual current canonical Note whose body exactly matches the visible attempt, or the associated authoritative **open** recovery buffer containing those exact bytes, is sufficient preservation. A different generation/closed local session is not by itself a reason to reject the canonical-match case. Another actor may already have Saved the exact visible text. Reading that fact grants no write/adoption authority and should not modify the local lifecycle.
- Otherwise try the existing checked first-dirty/buffer preservation. Re-read the authoritative relevant session/current Note when the result is ignored, closed or stale; the cached session and a successful-looking `None` from `note_changed` are insufficient. Permit ordinary exit only if preservation is actually established; a conflicting newer buffer with different text, `EditSessionOpen` with different text, or a write/read error must not silently admit loss. Preserve exact old base/session/generation semantics; do not force-update to another actor's generation or auto-Save the canonical Note.

The current void `preserve_visible_note_input` cannot be the boolean admission check: it discards the result and deliberately skips blocked/hidden input. Inspect the held canonical Note even when its tile is hidden/read-only; `BlockedElsewhere` is exactly a state with possible live-only bytes. The separate review editor and unsent comments/Ask drafts remain outside this slice. No all-record scan, new cache, table or lease is justified.

**Avoid a new exit trap.** With a newer open recovery buffer, existing explicit validated Recover is a normal resolution; U4's confirmed Discard-other-edit can instead retain this view's text through a new checked session. But the closed-local-session edge has no guaranteed current escape: `discard_note_session` returns `Newer` for an already closed session (`note.rs:304–335`), non-explicit open is refused by PR209, and explicit Recover requires an actually open buffer (`note.rs:122–136`). Thus a notice saying only “Recover it from Home” is insufficient when no buffer exists. Merely copying the Reload guard would introduce a cannot-quit state even after an exact-body external Save, and would still strand genuinely live-only closed-session text.

The narrow complete design is automatic preservation admission plus, when it fails, **keep the window open by default with an explicit Note-only discard-and-exit consequence choice** using the existing consequence-dialog control. That confirmed action discards only the captured live attempt; it must not call Store discard on a newer/different recovery generation or alter canonical data. Bind it to the captured Note ID, exact visible bytes and local session/generation; if that local intent changed while the dialog was open, reject/re-evaluate rather than applying stale confirmation. It can use explicit teardown after confirmation instead of a persistent bypass flag. Alternatively an implementation could preserve a fresh checked historical-base recovery session, but that additional lifecycle transition is not selected here. A veto-only implementation must demonstrate a real existing escape for the closed/mismatched case before it is adequate; external clipboard copying plus force-kill is not a normal recovery route.

Perform admission before teardown effects. On refusal notify and return false for Close / omit `cx.quit()` for Cmd-Q. Once preservation or exact confirmed local discard admits exit, retain the existing continuation-discard, worker cancellation and conversion cancellation before closure/quit. Do not move persistence into `on_app_quit`, which cannot veto. This preserves current-data guards rather than weakening them to make exit possible. Admission establishes a checked preservation point, not immunity from later authorized concurrent mutation or forced termination.
