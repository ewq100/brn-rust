## Source assessment and necessary fixture condition

`threads_projects.rs:131–148` commits through `workspace.project_command`, handles Run retirement, confirms and refreshes host records, but does not replace Connections. `threads_connections.rs:207–210` retains a completed graph while its centre ID matches the open Note. Async acceptance at `:109–123` checks request generation, which project mutation does not advance. Those facts support both completed-result retention and an older completion surviving the transition; they do not themselves prove a fixture loses access.

Actual access remains correctly owned by SQLite/core context. `context.rs:20–41,43–63` checks current Project membership for Notes and retained sources; app `search.rs:1345–1350` refuses a Connections centre absent from current searchable Notes, and its neighbours use the scoped snapshot path. `projects.rs:154–182` includes explicit documents, active Project↔Note Links and Notes in Project chats. Therefore deleting one displayed document link is not sufficient proof of revocation if another source of visibility remains. `UnlinkDocument` also refuses removal of an exclusive Project-owned Note without another retained Project (`projects.rs:508–517`). A meaningful witness needs a private Note/source whose origin scope remains valid elsewhere but whose selected target Project has genuinely lost its last access path. Do not bypass that service guard or “fix” a still-visible fixture.

Displayed `note_project`/`note_writing_scope` should continue to identify the origin selected when opening the Note. Losing that context's access is not permission to rewrite those fields to general or another Project, close the editor, or overwrite a recovery buffer. This is retirement of a delayed derived view, not a writing-scope migration.

## One minimal ownership choice

Keep `refresh_connections` as the single owner of replacement. It already increments generation, drops task/cancellation, clears result/error/pending, retains depth/filter/source preferences, and requests through the existing asynchronous visibility-checked service only when the tile/open Note warrant it (`threads_connections.rs:61–103`). Its generation check prevents an older completion from replacing the new state. A revoked centre may produce the existing failure/empty state; it must not preserve old labels or silently widen scope.

Invoke that existing operation after `apply_project`'s successful canonical refresh, covering the entire common Project-command family rather than only Unlink's button. Also invoke it after `undo_receipt`'s existing refresh/reload boundary (`threads_ui.rs:2525–2532`). Undo can reverse membership but currently `reload_open_note` only refreshes the writing Note/records and marks (`:2492–2499`); it does not re-request Connections. Conservative replacement after the existing Undo reconciliation is acceptable without inventing a receipt classifier. Failed/unapplied Project commands should retain their existing error behavior.

These are two existing mutation-family entry points calling one existing view owner, not two copies of a visibility guard. No database read in rendering, new project-membership fingerprint, per-keystroke polling, index scan, full canonical-read API, or conversion of every `refresh()` caller to accept UI context is needed. `refresh()` is used for typing, setup, settings, navigation and worker progress too; unconditional Connections replacement there would create unrelated churn. Existing open-note, tile-open, depth/source and recenter request callers remain responsible for those transitions. Every graph query continues off the UI thread; this repair adds no render-time authority checks or synchronous graph traversal.

## Witness expectations and qualification boundary

The before-source test should first establish a real previously populated scoped result and actual rendered private/source labels, execute the supported Project callback, then independently prove canonical visibility is revoked. Observe the stale result/rows on unchanged production source at an immediate rendered frame before draining background work. A failure before that intended assertion, or a fixture that retains visibility, does not reproduce this hypothesis.

The corrected journey should show immediate retirement and no old labels, then no reappearance after executor completion; preserve exact Note/source bytes, ownership, selected scope, open editor/recovery state and the sole intended membership effect. A meaningful Undo membership case should also bind actual public Undo to current visibility and fresh Connections, particularly Undo of a link that revokes access. Reuse existing navigation/depth/filter witnesses rather than duplicate them.

Pending-request retirement is partly covered by unchanged generation/cancellation mechanics. If the test can exercise an actual pending pre-transition request deterministically using existing facilities, retain that phase; otherwise state the source reasoning/qualification limit instead of inventing a worker hook or claiming a race was observed. No provider worker, native interaction or owner data is required. If the baseline cannot prove revoked visibility or cannot reach the intended retained-view assertion within the task's selected attempt bound, reassess/defer; do not implement from this design inference alone.

Excluded: automatic cross-process change detection, other delayed consumers, knowledge-check snapshot policy, general graph correctness, switching writing scope, privacy-policy/schema/index changes and a universal freshness framework. Complete source review and actual candidate gates remain separate.
