## Finding: stale private-note text can be copied into general BRN knowledge

**Trigger:** The owner opens a chat-scoped Note and edits it. A valid example is an imported private Note: `Workspace::attach_full` constructs it with `protected=true`, `chat=Some(chat)`, and import/source metadata (`crates/brn-threads-app/src/intake.rs:471–480`). The owner can use the Note menu's “Make working note” command (`crates/brn-writing-ui/src/writing.rs:227–249`); desktop `toggle_protection` changes only `protected` on the current checked Note (`crates/brn-desktop/src/threads_ui.rs:2534–2554`), leaving its `chat` scope intact. An unprotected chat-scoped Note is also reachable through the real desktop project-note route, as `a_shared_private_document_uses_the_selected_projects_writing_chat` demonstrates (`crates/brn-desktop/src/threads_projects_tests.rs:171–185`). After typing, a later checked writer can advance the saved Note so the owner sees the ordinary stale-edit Save as new note control.

**Effect:** `ThreadsUi::save_copy` takes the visible editor text, uses the source Note only to form a title, and calls `Workspace::new_note` (`crates/brn-desktop/src/threads_ui.rs:4685–4699`). `Workspace::new_note_with_key` creates `Note::working(title, markdown)` with no source inputs (`crates/brn-threads-app/src/lib.rs:335–359`); `Note::working` sets `chat=None`, `protected=false`, `import=None` (`crates/brn-threads-core/src/types.rs:16–38`). The copy therefore becomes an ordinary general Note, without the private source Note's chat scope or its checked source/import relationships. `Workspace::notes()` includes every current Note whose `chat` is `None` (`lib.rs:283–291`), and general owner search uses `search_page(..., None, ...)` (`lib.rs:546–550`). This silently makes the private text general/searchable when the visible action promises only a “separate working note” (`crates/brn-writing-ui/src/writing.rs:734–742`). The creation request also does not bind the private source Note ID/version or check its current scope/archive status.

This bypasses the existing private-content boundary: the invariant states general search/export excludes private content and private provenance survives movement/Undo (`docs/architecture/invariants.md:38–46`). The action is an explicit click to save a copy, but it does not use the separate explicit `Keep in BRN` operation, and its wording does not indicate that it publishes the private text to general Notes/search/export.

## Existing evidence and closest checked reuse

- `crates/brn-desktop/src/threads_polish_tests.rs:472–514` proves the real dirty-stale UI displays and invokes Save as new note, and asserts that the new Note contains the visible text. It uses a general fixture; it does not assert or exercise private scope.
- `crates/brn-desktop/src/threads_projects_tests.rs:171–185` proves a `Note` with `chat=Some(source_chat)` is openable from a project that shares it while the canonical Note remains chat-scoped.
- `crates/brn-threads-app/tests/chat.rs:264–364` proves a private full-note attachment remains absent from general notes/search/export and after restore; explicit `keep_in_brn` makes that same protected Note general/searchable, and Undo removes it from general Notes/search again.
- `Workspace::keep_in_brn` is the closest existing checked privacy-boundary operation (`crates/brn-threads-app/src/intake.rs:563–630`): it binds the operation to Note ID/version, refuses archived or stale source records, and intentionally changes the same Note from `chat=Some` to `chat=None`. Its continuation preserves owned source/assets/links. It does not create a recovery copy of edited visible text, so routing Save as new note through it would promote the original instead of preserving the intended copy.
