# Reference-search freshness after Project membership changes

**Disposition: no-change.** A checked Project unlink or its Undo advances the canonical `Store::change_token`; a pending scoped search and any accepted-but-not-yet-attached match are then hidden/refused until explicit recheck. No source-backed stale-display or stale-attach path was found.

Source baseline is integrated `origin/main` `10f2ff80a39408ce411e10c77200e6d4a89b12d3`; inspected Connections-fix commit `317360bd46a64c002e1dabba961de755b6226355`. Its only delta from main is `threads_projects.rs`, `threads_tiled_tests.rs`, and one `threads_ui.rs` call after Undo; reference-search/setup code is unchanged. The lead checkout also contains unrelated dirty campaign/evidence documentation, which I left untouched.

`search_writing_references` captures the setup `target` and `observed` token, clears old matches, and submits `request_page` using the captured scope (`crates/brn-desktop/src/threads_ui.rs:4039–4101`). Completion first checks request generation and exact retained draft identity, then `writing_setup_form_current`; a matching reply always retires pending, but returns without assigning page matches/cursor/count when the form is no longer displayed/current (`:4104–4140`). `SetupDraft::displayed` requires the same displayed Note/scope and exact current `change_token` (`crates/brn-writing-ui/src/setup.rs:155–167`). That token includes the max canonical revision rowid and `PRAGMA data_version` (`crates/brn-threads-core/src/store.rs:232–251`). A real Project membership write and its compensating Undo both create revisions, so even an Undo that restores access does not make the old observed token current again. Explicit recheck reloads a fresh token and clears pending search state/matches.

Already accepted matches have the same fence: the setup drawer refuses to render its reference labels/results when `displayed` is false (`setup.rs:314–320`); the `AttachReference` callback and `SetupDraft::attach_match` each recheck it (`threads_ui.rs:4417–4434`, `setup.rs:193–220`). Attachment then verifies the Note is active at the matched version and retests the token. Persisting a new reference goes through `Workspace::set_writing_setup`; core validates current scope and visibility for newly added references (`brn-threads-app/src/writing.rs:411–452`, `brn-threads-core/src/writing.rs:483–505`). Existing unavailable links are represented with no usable version and may be retained/removed, but do not become newly attached search results.

Existing evidence covers the component guards: `b3_delayed_scoped_search_reply_cannot_publish_titles_or_counts_into_another_form` checks that a canonical access change before completion leaves matches/count empty (`threads_writing_tests.rs:3710–3797`); `b3_setup_labels_and_drafts_fail_closed_on_scope_switch_and_notify_only_revocation` checks Project-change token invalidation and hidden displayed labels (`:2461–2620`). The PR204 qualification and review receipts record the existing delayed-search test and owner-boundary assessment (`evidence/reference-search-owner-qualification.json`, `evidence/reference-search-owner-review.md`). These do not specifically unlink a search-hit Note from a Project; the no-change conclusion for that event follows from the general revision token and same display/attach gates, not from claiming that exact scenario was run.

Read-only source/evidence assessment only; no test, build or runtime action was performed. No further task is suggested unless those token/display gates change.
