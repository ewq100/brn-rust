## Current lifecycle and field ownership

- `ThreadsUi::new` reads canonical `WorkspaceSettings`, creates `ProviderForm::from_settings`, then initializes four separate `InputState`s for model, auth path, credentials path and helper model from saved settings (`crates/brn-desktop/src/threads_ui.rs:447-450,472-496`; `crates/brn-desktop/src/threads_state.rs:12-35`). Segmented controls edit only `provider_form` (`crates/brn-desktop/src/threads_tiles.rs:1512-1535,1537-1577,1611-1669`). The four text fields edit their `InputState` entities (`threads_tiles.rs:1564-1589,1648-1656`).
- Every call to `ThreadsUi::refresh` rereads records/history/settings, replaces `provider_form` from saved settings, and assigns `self.settings`; it does not reset any of the four input entities (`crates/brn-desktop/src/threads_ui.rs:782-791`). This produces a mixed form when a text field is dirty: segmented values revert, text values remain.
- Ordinary navigation reaches this refresh through `show_tile`, which is the shared open-tile route and runs for Settings as well as other tiles (`threads_ui.rs:980-989`). Opening a note and opening a chat also refresh (`threads_ui.rs:1219-1220,1248-1251`). Switching Settings subsections only changes `settings_section` and rerenders; it does not call refresh (`threads_tiles.rs:1851-1871`). Layout changes use `relayout` and do not refresh (`threads_ui.rs:990-1002`).
- Refresh is also called after many unrelated actions and state updates. Two clear asynchronous examples are worker completion and converted-import completion (`threads_ui.rs:2826-2835,2837-2935`). The worker poll loop checks every 80 ms, but the timer itself does not refresh; delivered events invoke the handling path (`threads_ui.rs:604-616`). Other command paths refresh after canonical writes, including explicit toolbar model/effort changes (`threads_ui.rs:2234-2271`) and Settings Save (`threads_ui.rs:3541-3571`).
- Save deliberately combines `provider_form` selections with the current model/auth/credentials/helper-model input values before calling the existing checked `workspace.configure` (`threads_ui.rs:3541-3569`; Save button at `threads_tiles.rs:1674-1698`). A later Save after refresh can therefore combine reverted segmented choices with retained text drafts. `configure_explicit` for toolbar choices refreshes, then explicitly resets only the model input to the saved model (`threads_ui.rs:2252-2271`); this is a special field update rather than a general text-form refresh policy.
