# Recovery-copy route audit

**Disposition: no additional shipped recovery-copy bypass found in the bounded caller scan.** The inspected product source is `main213` `3827d6a13953533c7322fd7157d975a32dee5cb2`; the audit checkout is docs-current `546aaf6583d404737cf5c19bf37d1c0b67765c27`, with no production source delta from that product source. Worktree was clean before and after. This was a source-only trace; no tests, builds, or runtime qualification were performed.

The desktop owns the only wired SaveCopy path found: both the writing UI's “Save as new note” controls emit `WritingRequest::SaveCopy` (`crates/brn-writing-ui/src/writing.rs:730-743,1671-1678`), and the desktop dispatches that request to `ThreadsUi::save_copy` (`crates/brn-desktop/src/threads_ui.rs:4504,4685-4717`). It binds the source record and `EditSession.base_version`, captured scope, visible editor text, and a key derived from session ID/generation/scope, then calls `Workspace::save_recovery_copy`. That shared service binds all request inputs; replays the same prepared/completed operation before rechecking eligibility; refuses captured scope, non-Note/inactive/superseded/private historical basis, and non-Note/inactive/superseded/private current source; checks general visibility of both; and commits a new working Note with Historical basis plus Current source-version inputs (`crates/brn-threads-app/src/writing.rs:53-130`). On refusal the UI leaves the recovery editor in place; on success it opens the receipt's new Note.

The independent `brn-writing-ui` example host is not a second implementation: its `WritingRequest` handler falls through to an explicit “Unavailable in this development host” notice for unsupported requests (`crates/brn-writing-ui/examples/writing_host/host.rs:393-477`), including SaveCopy. I found no example-host callback that creates a Note from the recovery buffer.

Other production Note creation found in the bounded scan is semantically distinct: blank desktop New Note calls `Workspace::new_note(name, "")` (`threads_ui.rs:1468-1484`); import creates a Note from converted source material while retaining protected/import provenance and a Source link (`brn-threads-app/src/intake.rs:452-495`); and saving a reviewed chat reply as a decision creates a protected/confirmed Note with a decision link and checked message/thread inputs (`brn-threads-app/src/decisions.rs:35-112`). These are explicit creation/import/Keep-in-BRN flows, not fallback copies of a dirty recovery buffer. `new_note` is a general owner creation API accepting supplied text (`brn-threads-app/src/lib.rs:335-360`), but its existence alone does not establish a recovery-copy bypass: no shipped caller in this scan feeds it an existing private Note's recovery text.

**Limit:** this was a bounded search of non-test Rust callers in `brn-desktop`, `brn-threads-app`, and `brn-writing-ui`, plus the named example host—not a proof about future external hosts or every arbitrary owner-authored Note creation. No further implementation action is supported by this scan.
