## Evidence

`ComposerDestination` distinguishes Home, Thread ID, and Note ID/context in [threads_state.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_state.rs#L24). `set_chat` saves the visible text under the old destination before switching and restores the selected destination's draft ([threads_ui.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_ui.rs#L1035)). `open_thread` routes through this switch; opening a note preserves the existing selected chat unless the chat is blank Home ([threads_ui.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_ui.rs#L1184); behavior contract: [threads-behavior.md](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/docs/architecture/threads-behavior.md#L47)). Startup reloads persisted destination-keyed drafts, and every composer change is saved with a monotonically increasing destination generation ([threads_ui.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_ui.rs#L436), [threads_chat.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_chat.rs#L237), [core chat.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-threads-core/src/chat.rs#L621)).

The real `ask` path captures the current destination and clears that draft only after `post_message` succeeds; failures report that text is preserved ([threads_ui.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_ui.rs#L2053)). The UI witness `composer_drafts_follow_home_and_each_thread` exercises Home/A/B switching, opening a Note while A is selected, posting into A, posting from Home, and a missing-thread post failure followed by recovery of the failed text ([threads_focus_tests.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_focus_tests.rs#L311)). State-level tests also verify a post clears only its own destination and Note drafts remain distinct ([threads_state.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_state.rs#L521)).

For a chat attachment, the UI resolves or creates a chat, switches to its Thread destination, and retains the composer text before opening the file chooser ([threads_chat.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_chat.rs#L788)). The selected chat ID is captured into the import worker and supplied to the checked full-note import when conversion completes, so later navigation does not redirect the attachment ([threads_ui.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_ui.rs#L2998), [threads_ui.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_ui.rs#L2812)). Conversion errors do not clear the composer; successful imports link the Note to the captured chat. An existing synthetic poller witness confirms the resulting Note is linked to the captured Thread and that unrelated writing setup/queue state stays intact ([threads_writing_tests.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_writing_tests.rs#L3115)).

Archive uses the checked archive operation and does not remove the chat draft in the inspected handler ([threads_ui.rs](https://github.com/ewq100/brn-rust/blob/bc8a08e64b0dc1e2b33ff181dfdb54b62f59f5e4/crates/brn-desktop/src/threads_ui.rs#L2092)); the send guard refuses archived destinations before clearing text. I found no individual chat deletion path in this bounded UI trace. Project deletion/Trash canonical behavior was excluded as instructed.
