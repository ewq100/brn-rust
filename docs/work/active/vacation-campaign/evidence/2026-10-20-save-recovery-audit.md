# Save/recovery lifecycle audit

**Result:** No actionable gap found in the requested slice.

**Source boundary.** Inspected `crates/brn-writing-ui/src/note.rs` (`open_note`/`load_note`, `note_changed`, `save_note`, `refresh_note`, `discard_note_session`); desktop host callers in `crates/brn-desktop/src/threads_ui.rs` (editor Change subscription, `preserve_visible_note_input`, note replacement/layout paths, Save and discard confirmation); writing banner actions in `crates/brn-writing-ui/src/writing.rs`; and the real synthetic writing-host journey witnesses in `crates/brn-writing-ui/examples/writing_host/journey.rs`. Also checked the architecture invariant that Save is bound to edit-session/generation, dirty guards survive recovery, and delayed work cannot overwrite newer typing.

**Why the key sequences are covered:**

- Normal typing reaches `note_changed` from the editor Change subscription. It establishes the edit guard and durably advances the buffer generation before returning. Save first reconciles the exact visible text, then saves the session ID/generation; a successful Save reloads current text, while refusal preserves the visible editor and session. `host_wires_first_dirty_guard_save_and_fresh_access_loss_before_render` witnesses real editor input, the durable buffer before Save, successful saved content, and access loss after save.
- When the note is replaced or hidden, the desktop host calls `preserve_visible_note_input` first. `open_note` also checks the current editor; a dirty state that cannot be durably reconciled blocks replacement. A blocked-elsewhere edit is not written into the other session. The saved text remains visibly reported as unsaved. No independent close path that silently drops an accepted durable buffer was found in this host slice.
- Delayed/stale session operations are checked by generation at the store boundary. `note_stale_save_refresh_recovery_and_discard_preserve_the_typed_base` covers stale Save, refresh, valid recovery, stale retry, confirmed discard, and a late update against the closed session. `note_newer_buffer_generation_refuses_save_and_discard_until_explicit_recovery` covers a higher persisted generation refusing both old Save and old discard. These are relevant sequence witnesses; no separate delayed callback in the inspected host bypasses them.
- Confirmed discard captures a session generation. If typing advances while the confirmation is open, the old generation cannot close the newer buffer and the UI reports that a newer edit was kept. Discarding another caller's open edit preserves and adopts the local visible text after closure; `note_refresh_does_not_adopt_another_edit_and_confirmed_discard_keeps_owner_typing` exercises real input and Save afterward.
- Same-note explicit Recover deliberately replaces a blocked local attempt with the authoritative kept buffer, but only after validating the recovery hint. The banner says the local typing is not saved, and `note_explicit_recovery_replaces_a_blocked_attempt_only_after_validating_the_hint` asserts that a bad hint changes nothing and a valid Recover selects the kept buffer. This is an explicit recovery choice, not a silent navigation overwrite.
