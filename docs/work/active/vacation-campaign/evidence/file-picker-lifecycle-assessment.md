# File-picker lifecycle source assessment

Scope: read-only inspection of clean `f79f6540276c00155ab3bc0d7f019f4ea5d00c9e` in `/Users/evokessler/.codex/worktrees/export-durability/brn-rust`. No builds, tests, native picker activation, provider use, or source edits were performed.

## Finding

No concrete reachable cross-operation destination or worker-loss defect found in the requested callback paths. Admission is checked after picker return, and the file-import path checks again at `convert_file`; the callback does not clear or replace a live worker. Reference-import admission additionally validates the captured note/scope and their saved versions before conversion, then validates again before attaching. Backup callbacks reject a live worker before changing the saved folder. Export callbacks funnel into `output`, which rejects a live worker before launching an export. The selected export folder is carried explicitly into the export destination.

A picker callback is not fenced by a monotonically increasing worker generation. If an operation starts and fully finishes before the picker callback runs, admission sees no current worker. That alone does not redirect the selected destination: ordinary attachment uses the previously captured chat destination (per the already-landed owner correction); reference import retains its captured note/scope target; export uses the returned folder; backup uses the returned folder as the explicit new preference. This edge can permit an old user-initiated action after an intervening completed operation, but source inspection shows no wrong-scope write from it. I do not recommend a generation fence based on this trace alone.

## Call evidence

- `choose_import_for_reference` rejects when initially busy, then checks `this.worker` again in the returned-path callback before calling `convert_file` (`crates/brn-desktop/src/threads_ui.rs:3117-3166`). A reference callback calls `SetupTarget::validate` with current open note and scope before conversion. Picker cancellation is a no-op; picker failure only calls `fail` (a notice setter at lines 991-996), so it leaves any current worker intact.
- `convert_file` checks `self.worker` again before starting conversion (`threads_ui.rs:3178-3193`). Its started worker stores the reference intent (`threads_ui.rs:3290-3310` region; worker construction carries `reference_intent`). On conversion completion the event loop reads intent/cancellation from that worker, clears that worker, then either reports cancellation/error or applies the captured reference path (`threads_ui.rs:2910-3015`). This callback does not resolve a replacement worker's intent.
- `SetupTarget` captures `note`, `scope`, note version, and setup version. Its validator rejects a displayed note/scope change and any changed note/setup version (`crates/brn-writing-ui/src/setup.rs:12-64`). `complete_writing_reference_import` imports into `intent.target.scope`, resolves only in that scope, and attaches only after validating the same target again (`threads_ui.rs:4252-4355`). Existing tests cover a wrong target after navigation and stale/revoked setup (`threads_writing_tests.rs:2637-2653`, `2705-2735`). The target intentionally binds note/scope, not whichever chat is currently selected.
- `choose_output` rejects a live worker before starting an export picker or backup flow (`threads_ui.rs:3316-3355`). `export_folder_chosen` passes the selected parent to `output`; `output` checks for a live worker before launching (`3357-3373`, `3441+`). Thus even though export completion has no separate guard, its second-level admission preserves the existing worker.
- `choose_backup_folder` has an initial busy check; `backup_folder_chosen` repeats the check before applying the selected directory, and only after a successful preference save optionally calls `output` (`threads_ui.rs:3375-3438`). Existing tests exercise busy callback rejection and verify the worker and folder remain unchanged (`threads_backup_tests.rs:246-260`), plus cancellation/error (`210-243`). Export tests similarly exercise a busy callback and preserve the worker/status (`threads_backup_tests.rs:80-190`).
