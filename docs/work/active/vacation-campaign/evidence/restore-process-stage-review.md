## Findings

**[P2] Publish the complete readiness payload before exposing its ready name.** Location: `crates/brn-threads-core/src/restore.rs:383–384`, coupled with parent `410–420`.

The child calls `fs::write(final_ready_path, stage_path_bytes)`. That operation creates the final file before writing all its bytes. The parent waits only for `ready.exists()`, then immediately reads and decodes the file. A scheduling interruption after creation but before writing, or during the write, allows the parent to observe an empty or truncated stage path and fail the direct-parent/stage membership checks even though staging and OS locking are correct. The polling interval does not establish a happens-before relationship. This weakens the intended deterministic process witness with an avoidable race.

Write the path into a distinct same-parent temporary readiness name, let the write close successfully, and rename it to the final ready name. The parent should continue to wait only on that published final name. This is a transient IPC publication boundary, not a power-loss durability requirement; no generalized harness or production hook is needed.

**[P2] Keep the killed stage present until the public retry being tested.** Location: `crates/brn-threads-core/src/restore.rs:459–465`, coupled with the final public restore/assertion at `474–477`.

After killing/reaping the child and proving its complete stage survives SIGKILL, the parent calls private `StagedRestore::create` to manufacture the preserved same-process full-stage witness. `create` calls `prepare`, and unchanged production `prepare` calls `stage::sweep_abandoned` before creating that new stage (`restore.rs:67–73`). The killed child's marker is now free, so that private call removes the very stage the final public `Store::restore` is claimed to sweep. The final `!reported.exists()` assertion can therefore pass because cleanup already happened before the public retry. It does not establish the stated public-retry transition or isolate the killed-process witness at that boundary.

Prepare and retain the same-process full stage while the child is still live, then kill/reap the child and abandon the full stage without another restore preparation before the final public retry. Alternatively, perform and assert the public retry immediately after killing before manufacturing the separate existing witnesses. In either arrangement, assert that the child's stage still exists immediately before the selected public retry, then is absent afterward. Preserve the original full-stage/wrapper-abandon and unrelated/source preservation checks. `StageDir::create` itself does not sweep, so the wrapper fixture need not create this intervening sweep.
