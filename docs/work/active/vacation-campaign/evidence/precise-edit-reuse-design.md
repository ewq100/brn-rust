- `crates/brn-ai/src/threads.rs:650-658` defines `read_note` starts and continuation as UTF-8 byte offsets. Thus a reader can compute an absolute range from `note.start + byte_position_within(note.markdown)` and `expected_text.len()`, but a model may still confuse Unicode character indices with UTF-8 bytes.
- `agent/BRN.md:41` already instructs use of exact Note/version, UTF-8 byte offsets, expected text, and no fuzzy search/relocation. `crates/brn-threads-core/src/writing.rs:398-415` provides `exact_writing_range`: it accepts only a stored version-bound range whose exact bytes equal the saved quote. It returns `None` for unresolved, mixed/missing mapping, stale mapping, empty range, or mismatch; it does not search.
- There is a reusable *algorithmic precedent*, not a directly reusable edit API, in `crates/brn-ai/src/threads_research.rs:1067-1085`: `unique_offset` uses `str::find`, returns the UTF-8 byte index, and returns `None` unless the exact quote occurs once (overlapping occurrences count). The adjacent `anchor` logic is research-specific and intentionally can relocate a citation within a version; that broader current/history verdict behavior must not be used as edit behavior. `threads_research_tests.rs` exercises the citation verification/relocation outcomes, not the local-edit authorization path.
