## Confirmed design and required implementation conditions

1. **Required explicit nullable fields belong in the DTO.** The identified missing-key risk is real. `threads.rs:546–619,2629–2690` performs raw complete-batch validation, but pinned Rig 0.44.0 `src/tool/contextual.rs:147–160,217–244` independently deserializes `T::Args` before `Tool::call`. `prepare_edit` then validates a reserialized `EditArgs`; a plain missing `Option<usize>` would already have become an explicit null. The proposed per-field `deserialize_with` without any field/container default is sound by source inspection: pinned Serde derive's `expr_is_missing` emits `missing_field` when such a field is absent, while the supplied function can deserialize explicit null through `Option::<usize>::deserialize`. Make this mandatory, not merely preferred. Test direct `serde_json::from_value::<EditArgs>` and actual typed Rig dispatch separately: both absent, start absent, end absent, explicit null/null, both mixed pairs, integer/integer, wrong scalar types, duplicate/unknown fields. Every omitted-key path must fail before operation allocation. Raw validation alone is insufficient.

2. **Preserve integer identity and replay order.** `Some(n)` serializes as the existing integer, so preserving field order and normal `Serialize` behavior can preserve historical argument bytes/hash. Freeze the golden against independently recorded base serialization/hash; do not compute the expected hash by serializing the new DTO in the same test. Prove replay with a genuinely pre-bound legacy binding, not just two calls under the new code. Keep live/current-access checks, argument binding and operation tracking before prepared lookup, and prepared lookup before later canonical version/text resolution. A retry of a prepared quote edit must return that exact immutable preparation after later Markdown changes; it must not repeat quote discovery first. Missing/ambiguous semantic refusals can retain an allocated, tracked but unprepared operation; distinguish that from a prepared candidate and from shape rejection before allocation. Changed mode/text/arguments under that key must conflict.

3. **One exact selector, no fallback.** Dispatch the pair explicitly: integer/integer keeps the existing range validation and byte equality check; null/null requires nonempty exact text and exactly one occurrence in the checked current full Note; mixed values reject. The effective range then enters the existing full-document guard and exact host construction. Keep missing/ambiguous quote, stale version, wrong integer range, non-boundary UTF-8 and wrong expected text separate from a successful preparation. The whole Note quote must still require complete model read coverage. A host search/read must never advance that coverage. Preserve current scope, active-note, metadata, project, protection/review, dirty/stale, Apply/replay, Continue and Undo witnesses.

4. **The shared primitive is appropriate and small.** Existing `threads_research.rs:1067–1087` already checks overlapping matches by looking again after the first UTF-8 character of the first match. A private child module shared by the two sibling consumers avoids coupling editing to research and requires no public core API. Its new empty-quote rejection must be explicit. Research's valid citation paths already reject empty text (`threads_research.rs:193–195,1154`), so that does not change a valid caller contract. Add direct cases for ASCII and multibyte overlapping duplicates, one exact match after multibyte text, missing/empty quote, and quote longer than text. Preserve research's `Cited` preference for a valid cited range even when that quote occurs elsewhere; uniqueness is only research's relocation fallback. Preserve existing relocated/stale/private-history outcomes and add a focused overlap regression to the actual research caller after moving the helper.

5. **Nullable schemas fit the inspected routes, with bounded proof still needed.** Existing local `provider_formats_tests.rs:5139–5140,5219–5273,5823–5837` exercise integer/null unions through ChatGPT Responses, Copilot Chat Completions and Copilot Responses, including required nullable fields on the strict route. This is credible compatibility evidence for the representation, not proof that the new tool works. Use the real `prepare_note_edit` runtime and budget definitions and fixture HTTP routes to verify explicit nulls survive into typed dispatch and the immutable binding. Preserve closed required keys and all existing tools/budget accounting; do not copy another schema. As a minor design correction, retain `end`'s existing `minimum:1` rather than the example's `minimum:0` on both properties; null remains permitted either way, and no legitimate integer end is zero. This keeps the advertised legacy numeric constraints unchanged.

6. **Guidance must teach the new explicit mode without expanding authority.** State null/null only for a nonempty unique exact current-version passage; duplicates require an explicit range. Any corrected arguments use a fresh key. A mismatched integer range must never silently activate quote selection. Keep whole-document read, Rewrite/helper refusal, review-first and host authority language intact. The prior guidance-only candidate's offset explanation may inform the final text, but it is a separate unmerged candidate, not automatically part of this implementation.
