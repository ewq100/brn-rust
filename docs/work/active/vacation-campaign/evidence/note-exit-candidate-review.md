## Findings and disposition

### P1 — keyboard Quit bypassed admission while the active Window was leased

**Valid at `6da`, fixed by source review at `155bb`.** Original location: `crates/brn-desktop/src/threads_ui.rs:4858–4871` in the registered global Quit listener. Normal keyboard dispatch invokes global bubble handlers while the active Window is still being updated. The callback synchronously called `cx.update_window` for that same handle; GPUI Pre has temporarily taken it from the App's window slot, so this returns an error. The error fallback called `cx.quit()` without ever invoking `request_exit` or its worker cancellation. On native macOS this permits termination with live-only Note text; in TestPlatform quit is a no-op, explaining the observed absent dialog.

Primary source: pinned GPUI Pre 0.3.9 `window.rs:6473–6480,6575–6591` invokes the global action during Window dispatch; `app.rs:3140–3203` takes the window from the slot and restores it after the callback; `app.rs:2201–2216` reports absent-window failure. The saved exact-6da desktop run failed at the Cmd-Q dialog assertion `threads_writing_tests.rs:1889`, after initial Close refusal/dialog/Enter/Cancel checks passed. This is a production callback bug, not an unsupported test key or justification to remove that assertion.

Final correction clones the WeakEntity for each action and uses `cx.defer` before entering `update_window`, retaining the same admission and cancellation path. The toolkit expressly defines App defer as end-of-effect-cycle scheduling after stack entities return (`app.rs:2326–2332`). Window reinsertion precedes outer `finish_update` effect flushing (`1313–1331`, `3140–3203`), so the deferred operation can access the restored Window. No test assertion was weakened. The callback's missing-window fallback now concerns a window actually unavailable after dispatch, rather than ordinary active-window leasing. The unchanged Cmd-Q assertion and complete final journey subsequently passed in the corrected exact-source desktop run described below.

## Remaining source assessment

`WritingPanel::preserve_note_for_exit` owns Note preservation, reusing checked canonical/recovery reads and existing `note_changed` writes. It first tests exact same-Note UTF-8 bytes in canonical data or an authoritative open recovery session, then tries normal checked preservation and rechecks actual durable bytes. It never treats a cached session or ignored write as proof. Exact canonical bytes admit exit even when another actor already Saved and closed the cached session, avoiding the closed-session exit trap. Errors/conflicting newer bytes refuse ordinary exit. It does not Save/publish the Note, adopt a newer session, force-update another generation or broaden privacy authority.

The existing `open_note` PR209 replacement guard and explicit same-Note validated Recover exception remain unchanged. Exit deliberately asks a different question—byte durability rather than permission to replace the editor—and therefore does not blindly duplicate its generation veto. Canonical body equality does not grant a write. The existing `recovery_buffers` read is reused at this explicit boundary, not introduced into per-keystroke/render policy; no all-record selector, cache, table or framework was added. No latency/disk-failure qualification is claimed.

The opaque `NoteExitSnapshot` is a reasonable small owner-held intent value: Note ID/version, exact editor text, owned session and blocked-state identity. Host code cannot synthesize its fields. Confirmation checks it again inside the deferred final teardown immediately before cancellation/finish. A changed local attempt produces a warning and leaves the window open; no bypass flag or Store discard is used. A matching confirmation can close only this local attempt while newer canonical/recovery data remain untouched. The shared consequence control keeps Enter inert and exposes actual Cancel/explicit danger controls. Its close-dialog-before-deferred-teardown ordering is coherent.

Both installed exit routes call one `request_exit`. Veto occurs before continuation discard, worker cancellation or conversion cancellation; accepted preservation/confirmed local discard retains the exact pre-existing cancellation effects. Hidden/read-only held Notes are not skipped. Review/comment/chat drafts and forced process termination remain explicitly outside this Note-only contract.
