## Requirement and correctness assessment

The narrow defect is supported by the actual baseline: after a checked store update advances an existing edit session, visible text can still equal its stale local session text. `note_changed` then returns early, and ordinary `open_note` previously reached replacement without discovering the newer durable generation. This is distinct from the existing Save and Discard guards, which already refuse stale generations.

The added check at `note.rs:94–104` is at the shared replacement boundary, after the existing visible-input preservation and before `load_note` can replace lifecycle, selection, editor or canonical comparison view. It reads the current checked session by the local session's identity and refuses a closed session or unequal generation. A missing session/read error also exits before replacement. Through the checked edit API, session identity/note/base are stable and buffer updates advance generation; comparison of generation plus closed state is sufficient for this selected boundary. No extra persistence write, schema, command/API shape, dependency or per-keystroke database read was added.

The guard deliberately leaves explicit same-note Recover available. Existing `load_note` checks that the supplied hint belongs to the requested Note and still identifies a current recovery buffer before assigning any panel state. It chooses the authoritative current buffer instead of trusting stale hint text/generation. A hint for another Note does not qualify for the same-note exemption; an invalid hint fails before replacement. This preserves the explicit owner choice and existing refusal behavior rather than auto-adopting a new generation.

A valid local session still navigates normally. Clean/closed panel state has no local editing session to recheck. Blocked edits retain their existing input-preservation refusal. The new guard does not change Save, Discard, refresh, recovery ownership or SQLite authority. The overall `open_note` operation still includes the pre-existing input-preservation writes when needed; this review does not claim every rejected open is globally read-only. In the reproduced equal-text stale-session case, the new rejection itself performs only the checked read and leaves the captured state unchanged.

Desktop context admission remains before panel replacement, and the desktop caller updates Note context metadata in the `Ok` branch. The guard's error follows the existing visible error path. This change is a transition-time validation, not a new cross-process atomic snapshot protocol or generation framework.
