## Recommendation

Implement one backward-compatible alternate input form on the existing `prepare_note_edit` tool: retain required `start` and `end` keys, widen each property's schema type to `integer | null`, and interpret exactly `start: null, end: null` as “locate this nonempty `expected_text` only if it occurs exactly once in the exact current Note Markdown at the supplied version.” Derive the UTF-8 byte start/end on the host. Keep the existing integer/integer form byte-for-byte and behavior-for-behavior unchanged. Reject one-null/one-integer, omitted keys, empty expected text, missing quote and ambiguous quote. Never fall back from any integer/integer request to quote selection when its range is invalid, non-boundary, out of bounds, stale or mismatched.

This is an engineering choice within the authorized selected task, not an unresolved product-policy decision. The selector expands only how one exact passage is located. It does not alter the existing target authority, proposal-only flow or owner review boundary.

## Smallest safe implementation shape

`crates/brn-ai/src/threads_note_edit.rs` owns `EditArgs`, the tool schema, argument validation and host range validation. Change `start` and `end` from `usize` to `Option<usize>`. Keep both keys in the closed schema's `required` list and use `type:["integer","null"]` on both fields, keeping `start.minimum:0` and the legacy `end.minimum:1`; descriptions must say that either both are byte offsets or both are null to request a unique exact quote. Preserve the required-key contract at every call path. A raw-object presence check in `validate_arguments` is useful but may not suffice: if a tool adapter deserializes `EditArgs` first, missing `Option` fields become `None`, and `prepare_edit` later validates the reserialized struct with present null keys. The preferred enforcement is a required-nullable field deserializer on both `Option<usize>` fields (for example `deserialize_with` calling `Option::<usize>::deserialize` without a default), plus raw-schema validation where available; verify it against the actual dispatch paths and tests before relying on it. A schema declaration alone does not prove runtime presence enforcement. Validate the pair as: `(Some(start), Some(end))` retains today's `start < end && end-start == expected_text.len()` condition; `(None, None)` requires nonempty `expected_text`; mixed values fail shape validation. Do not add an occurrence field or new tool.

`prepare_edit` already validates argument shape, checks live/current access, hashes the complete args, allocates/binds the operation, records it on the Run and returns a previously prepared operation before reading later canonical Markdown (`threads_note_edit.rs`, current source around lines 82-128). Preserve that order. Only after replay lookup, exact target/version checks and active Note checks, resolve the effective range. Integer/integer follows the current `markdown.get(start..end) == expected_text` path without fallback. Null/null calls the exact unique-range primitive against only that current Note's Markdown; if it returns no range, return Invalid without preparing a candidate. Then run the existing whole-document read guard against the resolved effective range, use it to construct the Note from the exact checked base and continue through the same checked preparation path. Keep the selector fields themselves in the immutable argument binding, so retries of the same selector replay the same allocated/prepared operation; changing from explicit offsets to null/null after an operation was allocated conflicts and requires a fresh key. Shape-invalid calls that fail before allocation retain today’s no-operation behavior.

Both production consumers are under `brn-ai`: note-edit and the research citation verifier. Put the tiny overlap-aware helper in a private `crates/brn-ai/src/threads_text.rs` module declared under the existing `threads` parent, with `pub(super)` visibility for its sibling consumers. Move/adapt research's `unique_offset` primitive there and return a byte range (the research caller can use its start); have note-edit use the same primitive. Keep the helper low-level: reject empty quote, return a range only when one exact UTF-8 occurrence exists, count overlapping occurrences, and perform no normalization or relocation. Research keeps its own `Anchor::{Cited, Relocated, Missing}` verdict and version/history policy; the shared helper only finds unique exact wording. This shares logic between the only two runtime consumers without a public core API, coupling note-edit to research, or adding a framework. The implementation review should check helper visibility and the private module declaration.

The selector operates over the exact current full Note, not just the slice the model read. It cannot pick a duplicate by occurrence, and it never searches another version. A unique quote in the current Note is the sole selectable range; this is the intentionally narrow behavior. A unique quote that spans the entire Note still resolves to `0..markdown.len()` and must hit the existing full-read guard.

## Compatibility and authority review

- **Argument bytes and request fingerprints:** `EditArgs` derives `Serialize`; changing the two field types to `Option<usize>` does not change serialization of `Some(n)`—it still emits the same integer in the same struct-field order. The existing SHA-256 binding over `serde_json::to_vec(&args)` therefore remains identical for every legacy integer/integer call. `None` serializes as explicit `null`, giving the new selector its own immutable identity. Freeze a golden serialization/hash for a legacy call and test replay of an already-bound legacy operation. Do not skip serializing `None`.
- **Invalid allocations and replay:** current semantic Invalid outcomes occur after request-key allocation, leaving an allocated-but-unprepared operation; identical retry must recover that identity. Keep allocation before version/range/quote validation and prepared-operation replay before reading later Markdown. Missing/ambiguous quote refusals may leave the same empty allocated operation, just as exact mismatches do today; they must leave no prepared candidate or Note mutation. Changed args under that request key must conflict. Tool guidance must tell the model to use a fresh key whenever it changes arguments after Invalid.
- **Closed provider schemas:** `PrepareNoteEdit::parameters()` and `core_budget_definitions()` both call `note_edit::schema()`; actual tool registration also uses that type. Keep all existing required fields and `additionalProperties:false`, changing only the two field types/descriptions. Nullable integer unions already appear in this codebase's strict tool schemas, and `provider_formats_tests.rs` exercises nullable `occurrence` across the provider route matrix. Still add a `prepare_note_edit` schema witness through actual runtime/budget definitions and the supported provider-format routes so providers preserve required explicit nulls. Raw validator must reject omitted keys even if the SDK deserializer would default an `Option` to None.
- **No budget or DTO expansion:** retain the existing tool name, one tool call shape, and existing `max_tool_rounds`; update no round accounting, provider/model settings, persistence schema or CLI API. The existing tool is registered for ordinary runs and omitted in frozen Rewrite/research-helper modes (`threads.rs` `PrepareChanges::for_scope` and `runtime_catalog!`). Preserve those gates.
- **Host invariants remain authoritative:** scope and target access, exact version, archived/superseded checks, byte-exact expected text, complete-read check for full Note edits, host construction from the canonical base, project bindings, dirty/stale/protected/review logic, candidate immutability, read-coverage accounting, Apply/Undo and Continue receipt replay are unchanged. No model-supplied authority or operation variant is added.
