**[P2] Make ordinary-command output capture bounded and preserve failure/timeout receipts.** Locations: `qualify.py:132–152` and call sites `296–306,397–399`.

`run_cli` captures all stdout/stderr in memory using `subprocess.run(..., PIPE)`, unlike the bounded task-file capture selected by the design. This is concrete for the intended valid fixture: CLI `created()` returns the created Record, so `note-create` emits the whole approximately 8 MiB Note in its JSON envelope (`crates/brn/src/main.rs:924–928,1206–1209`). It should use bounded prefix files plus full-stream byte counts/hashes for ordinary commands as well, without dumping the Note body to tool output.

More importantly, on nonzero exit the helper constructs `receipt` and then raises before returning it. The caller's `commands.append(run_cli(...))` consequently never records the failure receipt. The reason claims hashes “are in the receipt,” but they are lost. On timeout, it records neither command receipt nor captured output identity. Persist/append each command attempt before propagating failure, including exact argv, actual exit/timeout, elapsed time, prefix paths and counts/hashes available. Timeouts must kill/reap the owned ordinary child, as `subprocess.run` currently does internally. This correction preserves the one restore-interruption-attempt policy; it is not permission to retry failed commands or repeat the workload.

**[P2] Treat required evidence/output capture failure as nonqualified, not success.** Locations: `qualify.py:174–189,393–395,434–446`.

The final receipt write catches any exception, prints only `receipt_write_error`, and then still returns zero if the success outcome was already selected. A successful run can therefore be announced even though the required durable receipt was never written. Set a failed evidence outcome/nonzero exit if receipt persistence fails, with an explicit stderr fallback identifying the failure.

The output-drain threads similarly do not relay exceptions to the driver, and bounded joins do not check whether a thread is still alive or whether its statistics are complete. A thread failure or unfinished drain must be recorded and prevent the final qualified outcome; do not silently accept empty `stream_stats`. Preserve bounded prefix output and full-stream hashes when capture succeeds. This is important for the selected reproducible evidence requirement, even though no account/private output is expected.

**[P2] Make owned-child cleanup unconditional across driver interruption and failed waits.** Locations: `qualify.py:192–197,335–347,387–395,425–442`.

Cleanup is attached to `except Exception` outside the observation scope, rather than the encompassing `finally`. A `KeyboardInterrupt` after `Popen` but before the inner observation `try` (for example during thread startup) bypasses that handler; the final block writes evidence/removes only the text fixture and leaves the restore child alive. The driver should enclose child lifetime in unconditional cleanup and preserve an interrupted/nonqualified result.

Also `stop_child_once` marks `kill_attempted` before sending the signal/waiting, then returns immediately on later calls when that flag is set. If `wait(timeout=10)` fails or signaling raises, the failure cleanup cannot retry a wait/reap even though it must not send a second SIGKILL. Separate “signal already attempted” from “process reaped”: at most one signal, but permit bounded wait/reap on cleanup and explicitly record any unresolved cleanup failure. Keep all actions on the actual owned `Popen` handle; no name/group kills or retry workload are warranted.

## Valid parts and source verification

The driver is inert without the explicit run flag. Its root checks require an absolute, nonexistent, nonsymlink canonical path before creation, check the parent's free space, and create root mode0700. This establishes freshness under the selected parent, not that an arbitrary argument lies outside every preserved workspace: the lead must select the already-authorized disposable parent outside owner/native data. Existing backup/workspace paths are never passed by this ordinary flow. No destructive cleanup recursively removes the root.

The public command paths were checked in actual source. `init --purpose test` uses `Workspace::create_without_default_credentials` and admits a missing/empty directory; precreating the empty source folder is valid. Subsequent `note-create --text-file`, `backup --destination`, and `restore --source` grammar matches the source. The four selected command families do not invoke ask/intake/model acquisition or configure a provider. The fresh workspace's credential source is absent by construction; environment masking and task-owned HOME/TMP further isolate it. No need for account/provider/network/native access is introduced.

`note_bytes` matches the real schema: `records.body` contains a serialized Record with `data.Note.title` and `markdown`. Snapshot comparison includes exact non-internal schema and all logical rows, including records, immutable revisions, operations and receipts. The SQL connection uses `mode=ro` and query-only. Normalization changes only the single workspace profile's purpose/changed_at and requires edit-session bindings already empty; this matches unchanged restore code's owner-profile write and cleared bindings. There is no SQL fixture creation, update, repair or normalization of arbitrary differences. Full Note UTF-8 bytes are separately compared, source rows/marker and backup hash are rechecked, and the sibling sentinel must remain exact.

The body bound is at most8MiB, backup check at most128MiB, free-space precondition at least2GiB, root-size checks after preparation/at completion at most512MiB, ordinary-command deadline60seconds and single observation window10seconds. The root size is a checked checkpoint bound, not an OS quota. Source and fixture are small/fixed; do not call this a hard resource-limit implementation. Ordinary output and failure cleanup issues above must be addressed to match the stated bounded execution/evidence policy.

There is only one interruption-child launch and no observation/retry loop that launches a new child. Missing the observation or natural child completion produces a nonqualified outcome and stops. The timeout cleanup kill, if needed after a missed observation, does not qualify partial-copy success. Public restore retry occurs once and only after actual `returncode == -SIGKILL`, absent final destination and retained staged workspace bytes strictly between0 and source-backup size. Post-kill sampling is appropriately required in addition to the pre-kill size observation. Comparing size to the standalone backup is conservative for this exact fixture; the full-copy stage may already be too large and the attempt may truthfully remain inconclusive.

`stage_sizes` currently recognizes direct children by prefix, rather than validating the production UUID/marker format, but it operates only in the newly created private parent, which is explicitly empty of stages before its single owned child. That fresh-parent/single-writer boundary supplies stage attribution for this task. Do not describe the helper as performing production exact-name/marker validation. The post-kill selected stage should ideally be tied explicitly to the same observed path in the receipt; current fresh single-child ownership prevents an ordinary alternate-stage false positive. A disappearing WAL during sampling can raise an ordinary exception and must remain a failed/inconclusive observation, with no repeat.
