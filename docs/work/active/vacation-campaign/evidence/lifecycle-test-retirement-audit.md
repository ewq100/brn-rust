## Disposition

No test retirement is justified from this bounded comparison. I found no direct unit-test layer in `brn-writing-ui` for `NoteLifecycle` or `ReviewLifecycle`: `note.rs`/`review.rs` have no `#[cfg(test)]` test module, while the shared crate's source unit tests concern other presentation helpers (`workbench.rs`, `layout.rs`, formatting/diff/theme). Its lifecycle protection is exercised by `examples/writing_host/journey.rs`, a separate disposable GPUI host with its own callbacks and real synthetic `Workspace` (`README.md:3-9`; `Cargo.toml:16-19`). The example is a consumer/host-contract witness, not a duplicate assertion-only reducer suite.

The desktop tests that resemble example journeys exercise a second, production host with different callback and admission paths. `ThreadsUi` owns a `WritingPanel` (`crates/brn-desktop/src/threads_ui.rs:329-331,456`) and adds host-specific scope admission, preserving editor/comment state, notice/error presentation, refresh timing, worker/candidate routing, visible controls, and Undo. For example, the shared host checks first-dirty event wiring and access loss before render (`crates/brn-writing-ui/examples/writing_host/journey.rs:185-264`); desktop stale-save/comment checks preserve the actual UI comment draft and refuse a stale quote (`crates/brn-desktop/src/threads_document_tests.rs:347-420`), and the late-completion race tests desktop reload timing against a typed buffer plus durable session identity (`:422-529`). These don't mirror the same host boundary.

Review examples overlap by invariant, but not by integration route. The independent host's edited-review journey types through GPUI, reopens the candidate, refuses old-candidate Apply, prepares a replacement, and handles late completion (`crates/brn-writing-ui/examples/writing_host/journey.rs:472-553`); its dirty-guard test uses the shared host's `WritingRequest::ApplyReview` (`:555-623`). Desktop review protection additionally exercises production candidate-card Apply against the currently edited candidate, the actual group-selection control, and cancel restoring the previous presentation (`crates/brn-desktop/src/threads_review_tests.rs:1853-1941`). The desktop review-state witness checks actual control availability, exact footer, and focus destinations (`:885-969`), which the example-host reducer assertions cannot replace.

The end-to-end Undo journey in the shared host (`crates/brn-writing-ui/examples/writing_host/journey.rs:32-183`) and the desktop workbench journey (`crates/brn-desktop/src/threads_workbench_tests.rs:84-294`) also have distinct ownership: the latter covers selected-chat retry, hidden Chat panel, comment-addressing, production cards, and persisted Workspace history alongside Apply/Undo. ## Boundaries retained

Therefore keep independent-host witnesses and desktop integration for dirty/version/recovery, provenance/current-context, review guards, and checked Apply/Undo. The narrow display/helper unit tests in `workbench.rs` are not Note/Review lifecycle duplications.
