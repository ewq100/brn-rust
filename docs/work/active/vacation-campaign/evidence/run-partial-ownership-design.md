# Run partial-answer ownership assessment

**Scope and basis.** Read-only source assessment on clean `codex/run-continuation-owner` at `413003efb5318127e6f63fd5d3c88bf6aa113de9` (as assigned). Existing completed slices are treated as fixed: `RunActivity` owns run-activity presentation and `WorkerOperation::Run` owns invocation identity plus its optional saved continuation. This note assesses only partial answer text. It does not propose or implement a generic reducer.

## Recommendation

Keep partial text as UI-owned presentation state for this slice; do not move it into `Worker` or add a new Run reducer solely for the string. The source shows a coherent production lifetime today: a Run worker is installed and the preview is reset after successful spawn; only its streamed/finalized output populates the preview; every production reader that associates it with durable Run work first obtains the current worker's Run identity; terminal and disconnect handling use the still-live worker and text, then retire both synchronously. Navigation leaves the worker and preview attached to the originating thread, and `stream_for(thread)` hides it from other chats. No reachable production state with a preview lacking a Run, or a Run preview attached to a different Run, was established in this inspection.

The useful coupling already exists at the worker identity lookup boundary, without making the worker own rendered text. Moving aggregation into `WorkerOperation::Run` is the smallest possible alternate: add a Run-only text value and replace/append/read methods, then delete `ThreadsUi::stream`. That would make orphan preview text structurally unavailable after worker retirement and remove the explicit clear calls, but it would also move output projection out of the host, contrary to `threads_worker.rs`'s stated boundary (“host still owns presentation”). The current clears are two explicit lifecycle sites, alongside the start reset; source does not show enough cleanup duplication or a reachable invalid combination to pay that ownership change now. Avoid a second `RunSession`/`RunPresentation` identity: it duplicates `RunIdentity` without demonstrated benefit.

This recommendation does not certify every ordering under all executions. In particular, source inspection cannot establish that all possible worker events or future call paths obey current assumptions. If a future change introduces another preview writer, a stale-preview defect, or more repeated cleanup sites, reassess by putting text behind the existing Run identity (prefer the host's narrow presentation boundary unless a worker-owned projection has a concrete consumer benefit).

## Current readers and writers

- **Initialization and lifecycle:** `ThreadsUi.stream` is a plain `String` beside the shared `Option<Worker>` and shared `progress` in `crates/brn-desktop/src/threads_ui.rs:413-417`. `start_run` installs a `Worker::run` after successful spawn, then clears the stream (`threads_ui.rs:2016-2027`). Run terminal handling clears worker, stream and progress (`threads_ui.rs:2813-2815`); disconnect first invokes checked preservation and then clears all three (`threads_ui.rs:2985-2999`).
- **Writers:** `poll_worker` replaces text on `AnswerFinalized` and appends `Text`, gated on the current worker not being cancelled (`threads_ui.rs:2676-2692`). The provider callback maps `AiEvent::Text` and `AnswerFinalized` into these events (`threads_ui.rs:1945-1957`). No production `Text` or `AnswerFinalized` producer outside this Run callback was found; tests synthesize them.
- **Checked preservation and partial use:** Stop-and-Send supplies nonempty text to `stop_and_post_with_partial` and only after success arms the existing worker continuation, clears the composer and cancels (`threads_ui.rs:2042-2074`). Ordinary stop supplies the stream to `stop_chat_run`, returns on failure before cancelling, and otherwise keeps it until terminal (`threads_ui.rs:2620-2644`). `pause_failed_worker` passes text to `interrupt_chat_run` while the old Run identity is present, or uses `recover_queue` for non-Run work (`threads_chat.rs:190-208`). Archiving passes text only when the current worker identity's thread matches the archived chat (`threads_ui.rs:2140-2158`; checked Workspace call). Project commands add `WithProgress { run, partial }` only under a current Run identity and non-whitespace text (`threads_projects.rs:117-133`); the checked project command remains authority.
- **Presentation:** `stream_for(thread)` returns text only if the current worker has a Run for that thread (`threads_ui.rs:2646-2653`). Writing view renders that projection only when the chat lacks its latest writing instruction (`threads_writing.rs:265-284`). The chat scroller includes stream bytes in its remeasurement signature (`threads_chat.rs:829-840`). The chat view also consumes text for its stop/interruption path (`threads_chat.rs:190-208`). Navigation therefore does not retarget or discard the active Run preview; opening an unrelated chat causes `stream_for` to return `None`.
- **Ordering:** Poll drains a bounded worker batch, checks Run terminal `(run,fence)` before handling it, and only handles the first terminal; terminal UI handling takes continuation and identity before dropping the worker. After the full old batch is consumed, a saved continuation is preferred over normal dispatch (`threads_ui.rs:2654-2673`, `2740-2815`, `2963-2972`; `threads_worker.rs:223-255`). Disconnect calls checked partial preservation before worker/stream retirement (`threads_ui.rs:2985-2999`). These orderings must remain if ownership changes. Workspace/SQLite still decides persisted Run/queue state; neither the preview nor local identity proves durable authority.

## Alternatives and cost

1. **Leave the current boundary (recommended).** Zero caller/API changes. Keep `progress` shared because imports, connects, exports and backups use it. Existing `stream_for` scopes presentation by Run identity, and the stop/archive/project effects obtain that same identity before supplying the text.
2. **Put `partial: String` only in `WorkerOperation::Run`.** No copied Run ID is needed because identity and partial would share the same enum variant; dropping the worker retires the preview. Retire `ThreadsUi.stream`, its constructor/reset/terminal/disconnect clears, and the old direct field reads/writes. Migrate mutation in `poll_worker`; stop-and-send, cancel, failed-worker interruption, archive, project progress and `stream_for`; the chat scroller's stream signature; writing preview; and tests that seed/assert `ui.stream`. Preserve `progress` in `ThreadsUi` and non-Run events. This is technically bounded but changes the documented worker boundary from channel/identity/continuation to also aggregating host presentation. Access methods would need to avoid returning partial for non-Run and preserve exact bytes; caller borrows around `workspace` effects and the poll loop would need careful handling. It removes explicit clear operations but does not remove a demonstrated production invalid state.
3. **Add another `RunSession`/presentation reducer containing identity and partial.** Reject for this slice. It duplicates the worker's existing identity and creates synchronization/invariant work at spawn, terminal, disconnect and successful project/archive fencing. Expanding it to progress, queue, cancellation, navigation or persistence would cross ownership boundaries and is outside the task.
