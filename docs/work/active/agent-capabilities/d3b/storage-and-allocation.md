## Small canonical representation

Propose one serde-default/empty-skipped `WorkspaceSettings.skills: Vec<SkillBinding>` (existing Settings JSON, no new table or backup format). Binding: exact ID, SHA256 package digest, optional exact project ID, enabled and selected flags. Unique(scope,ID), at most one selected binding per scope; selected requires effective enabled and exact digest. Built-ins keep existing default enabled behavior unless explicitly disabled; installed packages default disabled. General/workspace bindings do not implicitly enable project packages: project skills require their exact project's explicit binding. Display origin project for such installed bindings; underlying artifact identity remains installed:name. No project Note/instruction string overload.

Owner selection is a persisted scoped preference, not a new per-queue payload or grant. Composer and CLI choose through the same checked policy service; future invocations consume current selection. Changing policy/selection fences existing Working invocations and never auto-restarts them. This avoids changing ThreadRunStart/queue/OwnerRequest interfaces or parsing user prose for selection authority. All non-built-in bodies still model-lazy; selection highlights an exact enabled ID for read_skill.

Canonical enablement/selection/digests survive existing SQLite backup as Settings revisions/receipts; package text stays excluded local configuration. Missing/damaged/mismatched exact bytes produce visible unavailable entries and refuse selected loads, never name/origin fallback/source lookup/download/default enablement. Explicit reinstall of the exact approved bytes can satisfy an already enabled canonical reference on a fresh run; a brand-new install cannot enable itself. Already prepared runs keep their frozen availability/content identity.
