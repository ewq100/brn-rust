## Exact ownership and behavior

Only three AI files change: existing `threads.rs`, new private `threads_continuation.rs`, new `threads_continuation_tests.rs`. Docs are under d2 plus minimal active plan/evidence/status links. Core/app/CLI/UI/permission predicates, guidance, auth, summary, budget, history/read/source/research routes, schemas, manifests and lock are untouched. No extra production allocation is needed.

`retain_progress` keeps existing required `summary` and byte-identical readable legacy summary-only persistence. New optional objective (768 UTF-8 bytes), remaining_work (8 × 256), open_questions (4 × 256) and operations (16 exact IDs × 256) are bounded; the complete readable Run.progress remains at most4096 bytes. Unknown fields, over-count or aggregate overflow reject before an effect. The model's plan/questions/progress remain explicitly unverified; prose is never parsed for done/authority. There is no new serialized record type.

References must belong to actual nonarchived same-chat Run.operations. Fresh operation_info and existing scope/current-record/revision predicates check exact identity, not ID prefixes or model claims. Only a persisted receipt renders Applied; prepared expected-version/current-input mismatches render Stale, and Allocated/Prepared/Retired/Missing stay explicit. Applied means that exact prior commit, even after later owner edits; it does not mean present text or task completion. Checked referenced IDs are carried into the current Run.operations through the existing fenced runtime update. Hidden/out-of-scope operation details are omitted without hidden IDs or counts. Returned receipt metadata has at most8 visible write IDs/versions and an explicit omitted-write count; no old Note text/assets. No grant, read-ledger coverage or candidate auto-Apply is inherited.

The optional continuation suffix is assembled once after existing current intake and before D1B summary/model dispatch: latest at most4 prior nonworking same-chat Runs, at most16 operation queries, report excerpts at most4096 bytes each and complete rendered block at most16KiB. Whole rows only; bounded coverage is explicitly not an exhaustive absence claim. Owner objective linkage uses the actual normal saved owner Message ID/version, excluding reserved metadata roles. All reported text is in an explicitly UNTRUSTED CONTINUATION block, never system authority. Fresh liveness/change-token checks surround the snapshot; actual subsequent reads/prepares/writes retain their existing fresh checked guards. The block stays frozen within the invocation and does not rewrite D1A history/prefix. If its actual rendered initial estimate does not fit, byte-identical mandatory input wins with a visible gap notice. Summary and whole growing-request guards still see the actual input.

After existing finish liveness/fence checks, budget/tool-round exhaustion with empty progress retains only a bounded768-byte excerpt and exact ID of the trusted posted owner Message, not guessed remaining work. Writing routes are excluded. Existing Failed/Interrupted/Completed, partial-output, attention/terminal/queue semantics remain; a final answer is not proof a write/action/delivery occurred. Late callbacks cannot save this fallback after a newer run or Stop. There is no automatic restart, schedule or additional provider request.
