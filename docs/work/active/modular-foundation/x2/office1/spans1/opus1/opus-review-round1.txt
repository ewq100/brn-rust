`1 + 2 + … + C = C(C+1)/2`

tuple comparisons. Across R rows, this new geometry pass can therefore require Θ(R·C²) work.

A concrete source-level trigger is a rectangular, unstyled table with C unit-width restart cells in row zero and matching continuation cells in row one. With 4,096 columns, those 8,192 parsed cells cause **8,390,656 lookup comparisons**. This is an analytical operation count, not an executed benchmark or timing claim.

The pinned parser limits each individual `gridSpan` to 1024; it does not cap the number of `tblGrid` columns at 1024. Its cell and XML budgets bound input parsing, while this added lookup loop consumes no iteration budget. Pristine dense construction and the unstyled fallback do not contain this particular quadratic lookup. Finite input limits do not make it linear.

Both `previous` and the current cells already follow increasing source-column order. Replace the repeated full search with a monotone cursor over the previous row’s active entries, preserving exact column/span matching and immediate-row continuity. Keep the correction local; no quota or parser-policy change is needed.

Verification should include several simultaneous chains across at least three rows, with chains ending or restarting independently and mixed widths.
