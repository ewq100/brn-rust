# All-current-kind API and fidelity map — source1b

Exact checksum-verified sources, static only. Registry root/source tree digests in [package ledger](package-ledger.json); source anchors in [source-anchors.json](source-anchors.json). This completes source availability for this prospective scratch profile, **not** runtime compatibility or canonical root resolution. Source1a non-PDF findings were partial then; this table explicitly supersedes only the statements named below. Public feature/type presence alone is not operational proof.

The common maintained entry is `xberg::extract(input: ExtractInput, config: &ExtractionConfig) -> Result<ExtractionResult>` (engine API). `ExtractionResult.results` contains `ExtractedDocument` (types/extraction.rs137): text, metadata, structured tables/pages/images/document/URIs and processing warnings. Structure must be requested; no Xberg type crosses BRN's existing schemas. Public Table.cells is Vec<Vec<String>>; the existence of richer TableCell/DocumentStructure variants does not mean each extractor populates them. BRN's prepared.rs remains authority for typed cell/value/formula/comment/link/span, per-page preview and MIME evidence.

## Additional document families (source availability is not admission)

Office feature compiles legacy DOC/PPT, RTF/OpenDocument/EPUB/bibliographic/Typst/org/DBF-style parsers and enables notebook→HTML. Email compiles MSG/CFB/PST/tempfile. Excel recognizes additional XLS/XLSB/ODS families; they are not BRN current-kind input mappings. The feature/registry list in ../formats.md remains the staged contract map. Additional iWork/Hangul/archives/WordPerfect/SQLite/image-OCR/audio/remote/model features are not in this scratch union. No macro/JS/script execution, arbitrary path/URI or native/model executable acquisition is approved by discovering their code. Each new actual route needs exact MIME/kind mapping, source/quotas and evidence gates.

## Named projector/checker coupling

Metadata admission is always used, never try-Xberg-then-old-reader. No second complete parser or flattened-text reconstruction. The retirement checker presently bans production roxmltree:: and OOXML namespace strings; any future projector must comply with that existing boundary or receive an **exact reviewed exception before code**, not weaken/disable the checker. The all-document objective is preserved; these are per-family implementation gates rather than owner scope questions.
