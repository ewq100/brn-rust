## Compatibility projection rule and concrete audit questions

One common Xberg invocation path per admitted kind. Project typed evidence from actual maintained native results/metadata. Do not invent cells, formulas, headings or provenance by reparsing flattened Markdown. A source-demonstrated missing contract gets a bounded named compatibility projector, always applied for that format and reported in converter provenance; not try-Xberg-then-old-reader and not two whole document conversions. Reuse maintained bounded components for the missing object only. Retire replaced full reader/dependency once the family passes; retain a dependency still genuinely required by a reviewed projector. 1a main-crate gaps are source findings only, PARTIAL for non-PDF; exact dependency implementation and actual runtime behavior await1b and tests.

| Family audit finding to establish | Smallest potential compatibility work (conditional; exact hunk after source) |
| --- | --- |
|DOCX native output lacks accepted tracked-revision/story/footnote/field identity|reuse bounded existing structured story/evidence projection for those objects; preserve raw values and reference gaps. Do not keep the full legacy conversion route or call flattened text complete. |
|PPTX result lacks notes/group image/caption/relationship/table coordinates|retain only the missing maintained typed slide metadata projector, same shared package/image budgets; replace text extractor once equivalent. |
|XLSX output flattens formulas/caches/comments/format display|project these exact typed facts with maintained calamine/package admission if Xberg does not expose them; cache unavailable stays unknown, no recalculation or normalization to0. |
|EML flattened body loses MIME/related alternatives/header/attachment scope|keep a bounded MIME-envelope/parent/CID join compatibility layer with existing cumulative part/depth/decoded quotas. Each admitted attachment uses the same family adapter; unsupported attachments remain unprocessed with located gaps, never cross-scope guessed joins. |
|HTML conversion normalizes away literal text/table/figure/source identities|use existing bounded DOM metadata projection only for required source-bound facts; compare exact substantive text and tables. Remote content remains inaccessible. |
|Plain text/Markdown extractor normalizes bytes|use the declared Verbatim identity policy; do not substitute normalized output. Zero provider and no native restriction/platform availability regression. |

For every family: first allocation/expansion, package/MIME recursion, image decoding, cache/font/temp/file access and diagnostic output are source-audited BEFORE accepting untrusted input. No hard RSS claim. Existing package admission may bound ZIP expansion but does not automatically bound native PDF, CFB or repeated internal allocations. Memory gaps follow the plan’s STOP gate, with precise enforced API/platform proposal or pre-operation supported-profile refusal—not a custom parser/framework.
